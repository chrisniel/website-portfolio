# Content Roadmap

## Phase 1 — Professional Content

Status: Completed.

- Add verified projects, skills, About information, experience, education, email, and GitHub profile.
- Keep private CV information out of the public site.

## Phase 2 — Real Project Media

Status: Partially completed. BantayGabi and Minecraft media are live; Kumpuni media remains.

- Eight approved BantayGabi development captures are published in the manual carousel.
- Three privacy-safe Minecraft screenshots are published in the archived case study.
- The current public media is optimized and recorded in the asset register.
- Choose Kumpuni media only when an approved image adds enough context for a useful case study.

## Phase 3 — First Interactive Model

Status: Implemented as a five-model click-to-load library; texture optimization remains optional.

- Select one model that represents the work well.
- Export and optimize it as `.glb`.
- Create a matching WebP poster.
- Test the pair locally and on a phone.
- Maintain the implemented `<model-viewer>` click-to-load behavior while optimizing the GLB.

## Phase 3B — Model Library And Technical Explanations

Status: Implemented with five approved models and their supplied rendered views.

- Keep the main BantayGabi page focused on the project story.
- Use one viewer on `projects/bantaygabi-models.html` for approved model entries.
- Add short, accessible definitions only to unfamiliar technical terms.
- Keep the whole-environment tour deferred until an optimized, permission-cleared web export exists.

## Phase 3C — Mixed Game Media And Multi-Model Navigation

Status: Eight real images and five model entries are implemented; real video remains later content.

- Add a manual mixed image/video preview to the BantayGabi overview.
- Use a semi-transparent desktop thumbnail rail and a phone-friendly horizontal rail.
- Load videos only after selection and never autoplay them.
- Remove gameplay context from the model library.
- Add model-selection cards, one reusable viewer, one to three angle images, and synchronized facts.
- Add future media only after ownership, privacy, spoiler, and optimization checks.
- Keep Kumpuni as a future prototype case study until approved media and stronger build verification
  exist.

## Phase 4 — Publish

- Use the configured `origin` repository.
- Push the `main` branch.
- Enable GitHub Pages from the repository root.
- Verify navigation, email, GitHub links, images, and mobile layout on the public URL.

## Later, Only If Needed

- Privacy-respecting analytics.
- Custom domain.
- External large-asset hosting.
- Backend/admin tools after manual updates become a real problem.
